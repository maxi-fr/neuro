## 3. Run the sweep

1. **Smoke test through the normal runner.** First run the existing condensed parity test. After the changes, test exact L1, fixed-schedule agreement, the 16 candidate schedules and their per-hold charges, and the existing plan acceptance path. Run each arm on one development seed and check release, horizon, objective subtotals, plugin loading, solver status, and timing. Compare the L2 replay with the 0.30 reference. Investigate any material difference in containment, charge, or applied current before using it as the baseline.
2. **Screen sparse settings.** Use development seeds 7000 and 7001. Hold L2 fixed at 0.30 for the quadratic reference. Sweep pure exact L1 on OSQP to find a setting near the quadratic arm's delivered charge with containment on both seeds. Separately sweep a **common** activation weight for Bonmin, grouped candidates, and homotopy, with both magnitude penalties zero. Then screen a small activation weight on top of the selected L1 weight using Bonmin. Select the sparse settings from these runs at 1.02 s. Use Chapter 6's charge target of **under 30 mAs** and inspect final seizing-region counts alongside seizure burden.
3. **Confirm and freeze.** Confirm the selected settings on all five development seeds **7000, 7001, 7002, 7004, and 7005**. Use the same weight across the three activation-only arms. If there is no setting that contains spread for all three, report the trade-off at a common weight. Freeze solver limits and continuation settings for the reported runs. If an activation search reaches its limit, record whether it returned an accepted plan or used fallback.
4. **Run the reserved comparison.** Pair OSQP exact L1 and Bonmin exact L1 plus activation on **7100–7109**, using the same L1 weight. Run the fixed quadratic arm on those seeds if the final figure shows all three controllers on a reserved seed. Keep the reserved results out of the tuning decisions.
5. **Package the outputs.** Save resolved configs, per-attempt solve times and statuses, per-seed outcomes, and applied-current traces under this experiment. Record the source revision, solver versions, input hashes, and the command used. Use `uv run scripts/run_comparison.py <manifest> --output-dir <experiment-batch-dir> --workers 1 --resume` from the repo root for the reported runs. Generate the summary and final report from the saved outputs.

### Timing and outcomes

Measure **mean wall-clock time per attempted replan** using the `replan_time` field. Start the timer before preparing the solve inputs and stop after plan selection. For grouped candidates this includes the full search. For homotopy it includes all passes and any refit. Include failed attempts and time-limit exits. Run serially on the same host and report failures and fallbacks alongside times. The existing `solve_time` field retains its earlier timing interval for other benchmarks. Compare the full controller update time to the 60 ms replan interval.

Report seizure burden, final seizing-region count, delivered charge, applied off time, and bouts. Define an off hold as all applied electrode currents at or below **1 µA** in magnitude after controller release. Track fallback off time separately. Report paired differences for the reserved runs, with off time as the primary outcome.
